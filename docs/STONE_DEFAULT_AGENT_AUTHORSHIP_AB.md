# Default Agent Authorship A/B

## Question

Does adapting a visible attempt-memory reference produce a valid restart-aware
controller more reliably than authoring the same controller from primitives?

## Design

Each author model receives the same live Stone help and exact N/T/M behavioral
contract. The only changed variable is the authoring condition:

- **scratch:** no reference implementation;
- **reference:** a checked-in reference selected with `--reference-source` plus
  instructions to adapt it.

Both generated programs run unchanged through the existing restart evaluator.
It requires two controller processes per attempt, pair-local model/run hooks,
retention of the deliberately failed run, exactly five revisions and three
current keys in M, hidden-action recovery in T and M but not N, complete
transition phases, bounded prompt use, final materialization, and clean
rollback.

The paired report records first-response pass, structural validity, behavioral
success, one diagnostic-guided repair attempt, author-model token use,
generated source size, runtime memory metrics, and reference/source similarity.
Diagnostics are bounded and redact the opaque action token. A failed arm
remains a valid experimental observation; `complete` only means every attempted
author or repair invocation returned a tool-free source output.

## Reproduce

```sh
python3 host/bench/eval_stone_attempt_memory_reference_ab.py \
  --run-root target/runs/stone-attempt-memory-reference-ab-v1
```

Results should be interpreted as paired trials, not as a general model-quality
claim. More models or repeated samples are needed before promoting the source
flow into a native helper.

## Trial v1 result

One paired `gpt-5.6-terra` trial did not support the hypothesis: neither arm
passed unchanged or after its one bounded repair.

| Measure | Scratch | Reference adaptation |
| --- | ---: | ---: |
| First-response pass | no | no |
| Initial structural validity | yes | no (`global` is unsupported) |
| Author input tokens | 16,044 | 17,584 |
| Author output tokens | 3,806 | 5,265 |
| Generated bytes | 4,855 | 10,392 |
| Repair structural validity | yes | yes |
| Exact M memory revision | 5 | 5 |
| Eventual full gate pass | no | no |

Scratch initially used an unsupported `tool` message role. The reference arm
correctly transferred the important failed-outcome retention policy but added
Python `global` state while restructuring the larger program. Their repair
outputs both recovered the hidden action, retained the failed run, produced all
four transition phases, and left no transactions open. They still violated the
turn-0 action contract because the memory/transcript hook appended retrieved
evidence after the current diagnostic instruction. In the reference repair
only T failed this condition; in scratch, T and M failed it.

This is evidence against distributing the current full loop as sufficient
authoring guidance. It also identified a concrete policy correction: projection
should normally be inserted before the newest caller message, leaving the
current observation or decision instruction last. The checked-in default now
uses that ordering. The trial artifact is
`target/runs/stone-attempt-memory-reference-ab-v1/aggregate.json`.

## Hook-policy trial

The default reference is now the smaller
[`attempt_memory_hooks.stone`](../examples/references/attempt_memory_hooks.stone)
fragment. It teaches only the policy details that were easy to get subtly
wrong in v1: pair-local hooks without ambient state, bounded projection before
the current instruction, same-key replacement, and completed-nonzero outcome
retention. The author model must still construct the attempt lifecycle and
agent loop itself.

```sh
python3 host/bench/eval_stone_attempt_memory_reference_ab.py \
  --run-root target/runs/stone-attempt-memory-hooks-reference-ab-v1
```

One paired `gpt-5.6-terra` trial gave a mixed but useful result:

| Measure | Scratch | Hook reference |
| --- | ---: | ---: |
| First-response full gate | no | no |
| Initial structural validity | yes | yes |
| Initial M memory policy | fail | pass |
| Initial M revisions | 4 | 5 |
| Initial N behavior | pass | pass |
| Initial T behavior | pass | fail |
| Full gate after one repair | pass | pass |
| Initial author input tokens | 16,047 | 16,831 |
| Initial generated bytes | 5,304 | 10,716 |

The scratch arm appended memory after the current instruction and missed one M
outcome revision. The hook-reference arm transferred all targeted M semantics:
correct prompt ordering, same-key writes, retention of the failed probe, hidden
action recovery, and exactly five revisions. Its only initial gate failure was
that the inner model did not recover the action from the intentionally noisy T
transcript; one diagnostic repair made that baseline explicit and passed.

Therefore this sample does **not** show an end-to-end authorship-rate advantage.
It does show that a small policy fragment can teach the memory-specific edge
cases without the unsupported-global failure caused by adapting a full loop.
The M projection used 793 input tokens versus T's 1,644, a 51.8% reduction.
The artifact is
`target/runs/stone-attempt-memory-hooks-reference-ab-v1/aggregate.json`.
